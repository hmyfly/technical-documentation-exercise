# Part 4: Adoption Strategy

**Show their problems first.** Run the checker on one team's docs and show them three concrete errors—missing scaffolding table, no entry point, broken onboarding flow. Frame it as a gift that finds bugs they didn't know existed, not a compliance tool. People adopt tools that solve their problems.

**Make it trivial to adopt.** Three copy-paste commands: run the checker, use the template, add the workflow. Propose new docs follow the standard; existing docs get a grace period. Provide an escape hatch (`# DOC-SKIP`) so teams feel in control.

**Find my first fan and amplify them.** One team will get it immediately. Partner with them for weeks 3–4. Once they see improvements (faster onboarding, fewer docs bugs), celebrate them publicly. Social proof beats mandates every time. Show before/after. Make adopters heroes.

**Measure what matters.** Track doc-to-first-code latency (target: <5 minutes), new hire onboarding time (target: 20% reduction), and violations trending down. Ignore "% of teams using checker"—it's vanity. When people see real impact, they adopt because it works, not because you told them to.

**Handle the team that refuses.** Dig into why: too busy? Don't see value? Don't trust the tool? For "too busy," frame it as time saved per person per year. For "don't see value," have a junior engineer try their docs—watching them struggle proves the problem. For "don't trust the tool," let them reject violations explicitly; listen to pushback and refine rules. Only escalate if they block org-wide adoption, and only with data: "Team X's docs cost us 40% longer onboarding than teams using the standard."

**This trades speed for durability.** I won't hit 100% adoption in eight weeks, but the teams that adopt will stay adopted because the value is real.
